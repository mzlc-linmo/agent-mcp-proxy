# Agent MCP Proxy 安装部署

核对日期：**2026-10-23**。本文针对当前 Docker Compose 管理版，命令均在**仓库根目录**执行，不是在 `doc/` 目录执行。适用 macOS / Linux 的 Bash 终端。

> 管理页使用明文 HTTP，仅绑定本机或可信局域网；不要直接开放公网。本文的“部署通过”区分容器/HTTP、管理员登录、设备连接和业务调用，不能用容器 `Up` 替代全部验收。

## 1. 先选择安装路径

| 场景 | 操作 |
| --- | --- |
| 全新部署，无管理员和私有配置 | 按第 2～6 节初始化**空 v3 目录**，登录后再添加服务、设备及授权 |
| 已有部署，重新构建或换主机 | 不运行初始化；先备份镜像、环境、私有配置与秘密，按第 7 节升级/迁移 |
| 从旧四业务域配置导入 | 阅读第 8 节；该路径可能在启动时连接设备并发布写操作工具，不是空目录安装 |

现有 [README](<../README.md>) 提供能力与安全边界。当前启动入口是 [Dockerfile](<../Dockerfile>) 中的 `uvicorn runtime:create_runtime --factory`，不是 `python proxy.py`。本项目不部署 Higress、数据库或其他 MCP 上游，也不需要编译前端。

## 2. 环境检查

```bash
pwd
docker version
docker compose version
python3 -c 'import sys, hashlib; assert sys.version_info >= (3, 11), "Python 3.11+ required"; hashlib.scrypt(b"preflight", salt=b"0"*16, n=16384, r=8, p=1, dklen=32); print("Python and scrypt OK")'
docker network ls
docker compose ls
```

要求：

- Docker 服务可用，安装支持 `docker compose` 的插件（当前本机为 v5.3.1，不限定必须 v2）。
- 宿主机 Python 3.11+ 且支持 `hashlib.scrypt`，用于初始化；Docker 内为 Python 3.11。宿主机执行管理员初始化**无需先安装** [requirements.txt](<../requirements.txt>)，运行依赖由镜像安装。
- 首次构建可访问基础镜像仓库、Python 包源、`nodejs.org`（Node.js 22.23.4 官方归档，校验 SHA256）和 npm 包源（按锁文件安装飞书官方包）；构建需要 BuildKit，只支持 Linux amd64/arm64。运行时需要访问实际授权的 MCP 上游及小智 WSS。
- 绑定地址确实属于本机。macOS 可用 `ifconfig`、Linux 可用 `ip addr` 查看；DHCP 地址变化后需要更新配置并重新创建容器。
- 不能有另一个代理同时连接相同 WSS。发现现有部署时不要继续按新安装覆盖文件。

## 3. 网络、环境文件与权限

### 3.1 设置环境文件

仅新部署复制模板，保留已有文件：

```bash
cp -n .env.example .env
id -u
id -g
```

编辑 [.env](<../.env>)，以 [.env.example](<../.env.example>) 为模板：

```dotenv
BRIDGE_UID=65534
BRIDGE_GID=65534
BRIDGE_ADMIN_BIND_IP=127.0.0.1
BRIDGE_ADMIN_PORT=18082
AGENT_DOCKER_NETWORK=agent-backend
ADMIN_USERNAME=admin
```

| 变量 | 设置要求 |
| --- | --- |
| `BRIDGE_UID` / `BRIDGE_GID` | 默认 `65534:65534`；必须与秘密/运行目录所有者配套。普通用户安装可填写上面 `id` 命令的实际结果，**不要填写 UID 0** |
| `BRIDGE_ADMIN_BIND_IP` | 必填；`127.0.0.1` 仅本机访问，LAN 使用本机实际的可信内网 IP，不能把 `0.0.0.0` 当访问地址 |
| `BRIDGE_ADMIN_PORT` | 默认 `18082`，容器内部固定 `8082` |
| `AGENT_DOCKER_NETWORK` | 外部 Docker 网络名称，默认 `agent-backend`；变量不是旧版的 `LINMO_DOCKER_NETWORK` |
| `ADMIN_USERNAME` | 默认 `admin`，无默认密码；用户名非空且最多 64 字符 |

Compose 生成 `ADMIN_ORIGIN=http://绑定IP:端口`。浏览器必须使用同一地址，不能随意改为其他 IP、域名或 HTTPS；服务校验 Host，修改请求还校验 Origin。

**环境文件不是容器的通用 `env_file`**：当前 Compose 只显式注入 `ADMIN_ORIGIN`、`ADMIN_ALLOWED_UPSTREAM_ORIGIN` 和 `ADMIN_USERNAME`。将程序变量 `ADMIN_CONFIG`、`ADMIN_HASH_FILE`、`BRIDGE_CONFIG` 写入环境文件不会自动改变容器路径；自定义路径需要同步修改 Compose 的 `environment` 与挂载。

### 3.2 准备外部网络

[docker-compose.yml](<../docker-compose.yml>) 将网络声明为 `external: true`，不会自动创建。选择与上游相通的已有网络，并在环境文件中填写它：

```bash
# 示例：仅当环境文件选择 agent-backend 时检查此名称。
docker network inspect agent-backend --format 'Network={{.Name}} Driver={{.Driver}}'
```

如果确为全新独立环境、已确认没有需要复用的网络，可创建后再检查：

```bash
docker network create agent-backend
```

若要访问 `http://higress:8080`，必须使用 Higress 所在网络并确保其网络别名为 `higress`；单独新建一个同用途网络不会让已有 Higress 自动加入。当前本机使用 `linmo-backend`，这不是其他机器的默认值。

### 3.3 创建受保护目录

```bash
mkdir -p secrets runtime
chmod 700 secrets runtime
```

目录由当前用户创建时，将 `BRIDGE_UID` / `BRIDGE_GID` 设置为该用户 UID/GID。原生 Linux 的 0700/0600 要求匹配**所有者 UID**，仅 GID 相同不够；Docker Desktop 的挂载所有者显示可能被映射，不能只比较容器内 `stat` 的 UID，应使用第 5.2 节实际读写/权限操作检查。使用专门服务账号时，由操作者设置相应所有权；不要通过 root 运行、`chmod 777` 或关闭只读根文件系统规避权限问题。

```text
宿主机路径                 容器路径                          挂载/权限
secrets/                   /run/secrets/                     只读；目录 0700
secrets/admin_hash         /run/secrets/admin_hash           文件 0600
runtime/                   /var/lib/linmo-proxy/              可写；目录 0700
runtime/config.json        /var/lib/linmo-proxy/config.json   文件 0600
config.example.json        /app/config.json                  只读；旧格式导入源
```

配置保存还会对运行目录执行权限设置、原子替换和持久化操作，因此仅给目录“可读”不够。Docker Desktop 如报告挂载被拒绝，应检查文件共享授权和实际路径，不要放宽秘密文件权限。

## 4. 新部署初始化（已有部署跳过）

### 4.1 初始化管理员

```bash
python3 doc/bootstrap_admin.py
```

[初始化脚本](<bootstrap_admin.py>) 交互输入两次密码，长度 12～256 字符，仅保存 scrypt 哈希，文件权限为 `0600`。不要把真实密码写入参数、Shell 历史、聊天或自动化示例。

- 如果提示 `Administrator hash already exists`，停止初始化并使用现有管理员；不要删除哈希强行重建。
- 缺失或无效哈希时，服务拒绝启动，没有默认密码或临时登录后门。
- 脚本受宿主机 `ADMIN_HASH_FILE` 环境变量影响；常规安装不要设置该覆盖变量，否则可能写到与 Compose 挂载不同的位置。

### 4.2 预置空 v3 配置

**推荐新部署先创建空服务/设备目录**。这样启动只提供管理功能，不会自动连接真实小智设备，也不要求旧四域业务 secret。

下面使用独占创建；已有文件会报错并保持原内容，不要删除已有配置来重跑：

```bash
python3 - <<'PY'
import json
import os
from pathlib import Path

path = Path('runtime/config.json')
fd = os.open(path, os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
with os.fdopen(fd, 'w') as stream:
    json.dump({'schema_version': 3, 'version': 1, 'services': {}, 'devices': []}, stream)
    stream.flush()
    os.fsync(stream.fileno())
print('Empty v3 configuration created; no devices enabled.')
PY
```

当前没有网页首次安装向导。**省略这一步不会自动创建空目录**，而会进入第 8 节的旧模板导入路径。

## 5. 构建与启动前检查

### 5.1 校验 Compose 并构建

```bash
docker compose config --quiet
docker compose build agent-mcp-proxy
```

构建输出镜像 `linmo/agent-mcp-proxy:latest`。管理员初始化脚本、测试文件不在生产镜像中；管理员脚本应在宿主机仓库执行。生产镜像复制本地静态页面，无需前端构建。

镜像同时内置飞书只读运行环境：`/opt/feishu-node/bin/node`（仅此程序，无 npm/npx）和 `/opt/feishu-mcp`（锁定的 `@larksuiteoapi/lark-mcp` 0.5.1，原生模块 keytar 在构建阶段编译，运行库 libsecret 保留在镜像中）。构建失败时先看 Node 归档校验或原生编译输出，不要跳过校验或忽略安装错误。新镜像可按 [README 的飞书镜像验收](<../README.md#飞书镜像验收>) 先用独立标签验证，再安排替换。

### 5.2 用容器实际身份检查挂载

以下命令覆盖默认入口，**不启动 Uvicorn、不连接设备、不调用 MCP 工具**。它验证管理员哈希、文件权限与运行目录写入能力，不打印密码或配置正文；在确认运行目录已经是 0700 后，以相同模式执行一次 chmod 验证权限，并创建、关闭一个自动清理的临时文件，不修改配置正文。不要删掉 `--entrypoint python`，也不要用直接运行默认服务代替预检。

```bash
docker compose run --rm --no-deps -T --entrypoint python agent-mcp-proxy - <<'PY'
import os
import stat
import tempfile
from pathlib import Path
from admin_auth import Auth

assert os.getuid() != 0, 'Container must not run as root'
secret = Path('/run/secrets/admin_hash')
config = Path('/var/lib/linmo-proxy/config.json')
for directory in (secret.parent, config.parent):
    assert stat.S_IMODE(directory.stat().st_mode) == 0o700, 'Directory must be 0700'
for path in (secret, config):
    assert path.is_file(), 'Required file is missing'
    assert stat.S_IMODE(path.stat().st_mode) == 0o600, 'Private file must be 0600'
    assert os.access(path, os.R_OK), 'Private file is not readable'
Auth(secret.read_text().strip(), os.environ.get('ADMIN_USERNAME', 'admin'))
config.parent.chmod(0o700)  # 验证保存时需要的实际操作权限，兼容挂载 UID 映射
with tempfile.TemporaryFile(dir=config.parent) as stream:
    stream.write(b'permission-check')
    stream.flush()
    os.fsync(stream.fileno())
print('Container UID, private file access, administrator hash and runtime write check passed.')
PY
```

预检不是配置迁移工具，也不校验业务凭据有效性。旧格式迁移需先完整备份；不要把 `CatalogStore.load()` 当只读检查，它可能迁移并写入配置。

## 6. 启动与分层验收

### 6.1 启动服务

确认预检通过、没有旧代理双连后执行：

```bash
docker compose up -d --no-deps agent-mcp-proxy
docker compose ps
docker inspect agent-mcp-proxy --format 'Running={{.State.Running}} RestartCount={{.RestartCount}} StartedAt={{.State.StartedAt}}'
```

容器名固定为 `agent-mcp-proxy`，默认 `unless-stopped`。Compose 没有 Docker `healthcheck`；`Up` 或 `up --wait` 并不能证明应用就绪。启动后若失败/反复重启，应先检查管理员哈希、配置和权限，不要不断重复启动。

### 6.2 HTTP 检查

将 `ADMIN_URL` 改成环境文件的实际地址，**不要直接照抄回环地址检测 LAN 绑定**。使用 GET，不用 `curl -I` 把未实现的 HEAD 行为误判为故障。

```bash
ADMIN_URL=http://127.0.0.1:18082
export ADMIN_URL
python3 - <<'PY'
import os
import urllib.error
import urllib.request

origin = os.environ['ADMIN_URL'].rstrip('/')
opener = urllib.request.build_opener(urllib.request.ProxyHandler({}))
for path, expected in [('/', 200), ('/static/admin.js', 200), ('/static/admin.css', 200), ('/api/session', 401)]:
    try:
        with opener.open(origin + path, timeout=10) as response:
            code = response.status
    except urllib.error.HTTPError as error:
        code = error.code
    assert code == expected, (path, code, expected)
    print(path, code)
PY
```

不带 Cookie 的 API 必须为 `401`；返回 `200` 不是“更健康”。`403` 通常表示 Host/Origin 不匹配。这里验证管理 HTTP，不调用业务工具。

### 6.3 人工登录与设备配置

1. 用配置的用户名和初始化密码登录；全新空目录应没有设备和服务。
2. 添加实际授权的 MCP 服务：Streamable HTTP 或 SSE，认证支持 none / Bearer / API Key。公网使用 HTTPS；可信私网目标需要明确确认。私网 HTTP 仅支持私网 IP 或 `higress` 这类单标签主机名，带点的 HTTP 域名会被拒绝；上游地址不能用回环 `127.0.0.1`，它也不代表 Docker 宿主机。
3. 执行“发现工具”，只初始化并列工具，但**会真实连接上游**，不是离线单测。
4. 新建设备，填写独立小智 WSS（含秘密令牌，不记录到日志）。设备默认停用、无授权。
5. 选择必要工具、启用、保存，再明确“应用该设备”。停用/删除会停止该设备连接；普通保存不会替换运行会话。
6. 核对设备 WSS 状态、上游状态与实际发布工具。`connected` 只证明 WSS 连接，工具发现不证明业务权限。
7. 若需要业务验收，使用已授权目标和最小影响操作；写操作/采集需明确确认，超时结果未知不能自动重试。

浏览器登录、第二台 LAN 电脑访问、真实语音/业务权限应分别记录结果。重启会加载最新保存配置并连接所有启用设备，因此不能将重启当无副作用的测试。

## 7. 已有部署升级、迁移与回滚

已有环境不执行第 4 节，不清空运行目录、不重置管理员。完整升级原则见 [README 的升级说明](<../README.md#7-升级停止与回滚>)；[旧回滚记录](<升级回滚.md>) 中的镜像名和备份位置是历史记录，**必须自行确认存在且与待回滚版本匹配**，不能默认可用。

1. 核对当前 Compose 项目、容器、运行镜像 ID、网络和挂载路径。修改前备份旧环境/Compose 配置，给当前运行镜像打独立回滚标签。
2. 先构建新镜像，成功后再安排停机。
3. 停止旧代理、暂停管理写入，将运行目录和秘密与旧配置一起备份到**仓库及构建上下文之外**的受保护目录。秘密目录不是加密存储，备份同样含真实凭据，保留权限并核对完整性。
4. 启动新代理，再执行第 6 节验收。只操作代理服务，不重启数据库或其他业务容器。
5. 回滚必须先停止新代理，再恢复匹配的旧镜像、旧配置、环境和秘密，验证权限/网络后启动。不能让旧镜像直接读取 v3 数据，不能新旧实例同时连接同一 WSS。
6. 已添加飞书只读服务后回滚到不含该功能的旧镜像：旧版本会拒绝含飞书服务条目的配置。先在新版本解除相关授权并删除全部飞书只读服务，或恢复添加飞书服务之前的完整配置备份，再启动旧镜像。

仅停止本服务：

```bash
docker compose stop agent-mcp-proxy
```

从旧项目 `linmo-mcp-proxy` 改名迁移时，新 Compose 不会自动接管或停止旧容器。先识别、停止旧代理并禁用其自动重启，再启动新名称；不要用全栈 `down`、`down -v`、`--remove-orphans` 或删除数据卷替代精确操作。

修改绑定 IP、端口、UID/GID、网络或环境后应重新执行 `docker compose up -d --no-deps agent-mcp-proxy` 让 Compose 应用变化；单独 `docker compose restart` 不会载入新的容器配置。保存的设备配置会在重建后生效，应事先核对。

## 8. 旧四域导入与 v3 迁移注意事项

如果私有配置不存在，[runtime.py](<../runtime.py>) 会从 [config.example.json](<../config.example.json>) 导入。默认模板要求下列文件均存在且容器可读，权限 `0600`：

```text
secrets/xiaozhi_endpoint   完整小智 WSS，必须有效
secrets/readonly_key       ops-readonly 凭据，必须非空
secrets/ai_key             ops-ai 凭据文件
secrets/operations_key     ops-actions 与 ops-collection 共用的凭据文件
```

- 模板固定上游为 `http://higress:8080/mcp/<业务域>`；修改模板需同时遵循旧导入器的 origin 校验。v3 新服务目录则不限 Higress。
- 旧导入还要求容器用户能读取 `/app/config.json`。只读挂载 `:ro` 不会授予读取权限；模板若为其他用户所有的 0600 文件，专用 UID 会读取失败。只调整经核对的文件所有权/必要读取权限，不递归放宽仓库或秘密目录。
- 默认旧导入会创建**已启用设备并绑定全部六个允许工具**，包括采用、拒绝和触发采集。不能描述为默认只读或无授权启动。
- 可选域凭据文件可以为空，但迁入 v3 后变成无认证服务，**不等于停用**；空文件不能作为权限控制。
- 原有私有配置已存在时，不再从模板/业务 secret 重新导入。日常应通过管理页修改，不能靠改模板覆盖运行配置。
- 旧 v1/v2 配置迁为 v3 时，程序在同目录生成一次性的旧配置备份（已有则不覆盖），然后原子写入 v3。空 v3 新安装不生成这种迁移备份，也不需要它。该文件不是每次升级的完整快照。
- 旧六工具的 `legacy-review` 兼容授权不等同于实际 Schema 哈希复核；迁移后应重新发现、复核授权并应用设备。

## 9. 故障定位与禁止的捷径

| 现象 | 检查/处理 |
| --- | --- |
| Docker 无法连接 | 先启动 Docker 服务，确认当前 Docker context；不要改业务配置 |
| `network ... declared as external ... could not be found` | 环境文件的网络是否存在；确认应复用还是创建，不要盲目改为其他网络 |
| 端口绑定失败/页面无法连接 | IP 是否仍属于本机、端口是否占用、Docker Desktop 挂载/端口转发状态 |
| `403 Origin rejected` | 浏览器 URL 是否与固定 Host/Origin 一致；不要关闭校验绕过 |
| `Permission denied` / 私有配置不可用 | 容器 UID/GID、目录所有者和 0700/0600；目录必须可写且可由容器用户设置权限 |
| `Valid administrator hash required` | 是否使用初始化脚本生成有效哈希；不要写明文密码代替哈希 |
| `Configuration initialization failed` | 是否漏建空 v3 配置而走了旧导入；核对模板引用的所有 secret 和 URL |
| JSON 无效或配置版本不支持 | 从已核对备份恢复或按版本迁移；不要清空文件强行启动 |
| 保存后未生效 | 明确应用目标设备；改共享服务后须复核并应用受影响设备 |
| 飞书提示运行环境不可用 | 镜像是否为含飞书运行环境的新版本；不要挂载宿主机 Node 或改用 npx 代替 |
