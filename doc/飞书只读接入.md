# 飞书只读接入

本文说明 Agent MCP Proxy 内置的飞书只读接入：能做什么、怎么配置、有哪些限制，以及部署和回滚时要注意什么。日常操作步骤也写在[用户使用手册](<Agent MCP Proxy 软件用户使用手册.md>)第 5.7 节。

## 1. 适用范围

- 以飞书**应用身份**（`tenant_access_token`）读取数据，不代表任何个人用户；不支持个人用户登录授权（OAuth）或用户令牌。
- 只提供下面 6 个只读工具，不能发消息、不能新建、修改或删除任何数据。
- 由代理容器内固定版本的飞书官方程序 `@larksuiteoapi/lark-mcp` 0.5.1 提供，经 stdio 与代理通信，不对外监听端口。
- 这不是通用 stdio 接入：管理页面和导入功能都不能填写命令、软件包、参数、环境变量或域名。

| 工具（设备上看到的名称） | 用途 |
| --- | --- |
| `im_v1_chat_list` | 列出应用所在的群 |
| `im_v1_message_list` | 读取群内的历史消息 |
| `docx_v1_document_rawContent` | 读取文档的纯文本内容 |
| `bitable_v1_appTable_list` | 列出多维表格中的数据表 |
| `bitable_v1_appTableField_list` | 列出数据表的字段 |
| `contact_v3_user_batchGetId` | 用手机号或邮箱查询用户 ID |

即使飞书官方程序将来出现其他工具，或某个工具被标为只读，代理也只发布和调用这 6 项。

## 2. 准备飞书应用

1. 在飞书开放平台准备企业自建应用。
2. 只为需要的工具开通对应接口的只读权限，具体权限名以开放平台各接口文档为准；发布应用版本让权限生效。
3. 让应用能看到要读取的资源：把应用加入目标群，或在文档、多维表格中授予应用访问权限。应用看不到的资源，工具也读不到。
4. 建议先用一个低敏感的测试群或测试文档验证，再扩大范围。

App Secret 只在管理页面的密码框里填写，不要通过聊天、邮件或工单传递。

## 3. 配置步骤

1. 打开“MCP 服务目录”→“新增”→“飞书只读”。
2. 填写名称、App ID 和 App Secret，点击“保存”。App ID 长度 1～256，App Secret 长度 1～8192，均不能含控制字符。
3. 点击“发现工具（不执行工具）”。发现只启动程序并列出工具，不调用飞书业务接口，因此**凭据错误时也可能发现成功**。
4. 进入设备详情，在该服务组勾选需要的工具，保存后点击“应用该设备”。添加服务和发现工具都不会自动授权任何设备。
5. 在设备上做一次低影响的读取，确认返回符合预期。

## 4. 使用限制

| 项目 | 规则 |
| --- | --- |
| 返回大小 | 每次最多 1024 个 UTF-8 字节，约 341 个汉字；超出即失败，提示缩小查询范围（例如减小 `page_size`）。代理不截断、不摘要、不自动翻页 |
| 返回类型 | 只接受文本；图片、文件等非文本结果按失败返回 |
| 权限错误 | 飞书返回的权限或业务错误一律按失败返回，不显示飞书原文，不自动重试 |
| 进程数量 | 全部设备合计最多同时运行 10 个飞书程序，发现工具也计入；满额时提示稍后重试，不排队等待 |
| 发现 | 同一服务同一时间只能有一次发现；初始化 15 秒、发现总计 30 秒超时 |
| 调用 | 单次调用 20 秒超时；超时或失败都不会自动重放 |
| 凭据保存 | App Secret 保存后不回显，编辑时留空表示保留；私有配置以文件权限保护（目录 0700、文件 0600），不是加密存储 |
| 更换凭据 | 更换 App ID 或 App Secret 会清空发现结果，所有设备上该服务的授权变为“待复核”，即使工具完全相同也不再发布；须重新发现，在每台设备重新勾选、保存并应用 |
| 停用与删除 | 停用或删除设备会停止该设备的飞书程序；应用设备时先停旧连接再建新连接 |

## 5. 运行环境与安全边界

- 镜像内路径固定：`/opt/feishu-node/bin/node` 启动 `/opt/feishu-mcp/node_modules/@larksuiteoapi/lark-mcp/dist/cli.js`，工作目录 `/opt/feishu-mcp`。不经 shell，不在运行时用 npm/npx 下载，镜像中也不含 npm/npx。
- 启动参数固定为 stdio、应用身份、中文工具说明、域名 `https://open.feishu.cn` 和上面 6 个工具；App Secret 只经环境变量传给子进程，不出现在命令行。
- 子进程环境只含固定项和该服务的 App ID/Secret，不继承代理容器的代理设置、`NODE_OPTIONS` 或其他飞书相关变量；每次会话使用 `/tmp` 下的临时 HOME，结束即删除。
- 会话结束、取消、超时或设备断线时，代理关闭输入、等待退出，必要时终止整个进程组并回收，释放进程名额。
- 容器保持非 root、只读根文件系统、丢弃全部 capabilities，不挂载 Docker Socket，不增加端口。
- 构建时 Node.js 22.23.4 官方归档校验 SHA256（amd64、arm64 各一个固定值），其他架构直接失败；飞书官方包按提交的锁文件 `npm ci --omit=dev` 安装，原生模块在构建阶段编译。

## 6. 部署与回滚

- 部署前备份当前镜像（打独立回滚标签）、Compose/环境文件、私有配置与秘密，按[安装部署](<安装部署.md>)第 7 节操作，只替换代理容器，不让新旧实例同时连接同一 WSS。
- 新镜像可先用独立标签做镜像验收，见 [README 的飞书镜像验收](<../README.md#飞书镜像验收>)。
- 回滚到不含飞书只读的旧镜像时，旧版本不认识飞书服务条目，会拒绝整个配置。应先在新版本解除相关授权并删除全部飞书只读服务，或恢复添加飞书服务之前的完整配置备份，再启动旧镜像。

## 7. 验证范围

已完成的是隔离验证：合成的飞书 stdio 服务、本地模拟的小智 WSS、真实 MCP SDK 协议，以及断网容器中的官方程序启动、工具列表和测试专用 HTTP 应答。它们**不证明**真实飞书凭据、权限或资源可见性已经可用，也不代表真实小智设备已经完成闭环。

真实验收需要另行安排：由管理员在可信的管理页面填写凭据，指定一个低敏感的测试群或测试文档，在一台测试设备上授权、应用并读取，记录发现结果、WSS 状态、实际发布的工具和读取结果。
